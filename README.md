# Archaeo Doc Pipeline

Конвейер структурного анализа археологических полевых отчётов из открытого архива [ИА РАН](https://archaeolog.ru/pub/elektronnye-polevye-otchety).

Отчёты — это сканы, в которых информация разбросана по разным модальностям: сплошной текст, таблицы, планы, разрезы, карты, фотографии. Обычный OCR извлекает текст, но не различает типы страниц. Конвейер сначала определяет, что находится на странице, а затем распознаёт текст и извлекает сущности.

## Что делает конвейер

Для каждого PDF-отчёта:

1. **Рендер страниц** — PDF → PNG, 300 dpi (Poppler).
2. **Предобработка** — оттенки серого, медианный фильтр, выравнивание наклона (поиск угла по дисперсии горизонтальной проекции). Бинаризация отключена: она ухудшает OCR (см. «Эксперимент с настройками OCR»).
3. **Типизация страницы** — по плотности «чернил» страница относится к одному из типов: `dense_text`, `figure_or_table`, `mixed`, `image_or_blank`.
4. **OCR** — Tesseract, русский язык, модель tessdata_best.
5. **Извлечение сущностей** — регулярные выражения: персоны (ФИО), годы, топонимы, археологические термины, периоды.
6. **Отчёт по документу** — CSV, JSON и `report.md` в папке `results/<документ>/`.

Затем `analyze_results.py` собирает результаты всех документов и классифицирует документы по профилю макета: `textual`, `mixed_layout`, `visual_low_text`, `hybrid_other`.

## Текущие результаты

Обработано 44 отчёта, 2031 страница. Цифры ниже получены исходной версией конвейера (200 dpi, бинаризация Оцу) — до эксперимента с настройками OCR. Повторная обработка корпуса на новой конфигурации — следующий шаг.

| Тип страницы | Страниц | Доля |
|---|---|---|
| `dense_text` | 889 | 43,8 % |
| `figure_or_table` | 792 | 39,0 % |
| `mixed` | 274 | 13,5 % |
| `image_or_blank` | 76 | 3,7 % |

Больше половины страниц корпуса — не сплошной текст. Значительная часть информации в отчётах находится в таблицах, планах и иллюстрациях, и для них нужен отдельный путь обработки.

### Качество OCR

Эталонной расшифровки нет, поэтому качество оценено косвенно: какая доля распознанных слов есть в словаре русского языка (pymorphy3). Подробно: [docs/ocr_quality.md](docs/ocr_quality.md).

| Качество страницы | Критерий | Страниц | Доля |
|---|---|---|---|
| хорошее | ≥ 85 % словарных слов | 58 | 2,9 % |
| среднее | 70–85 % | 152 | 7,5 % |
| плохое | < 70 % | 1139 | 56,1 % |
| пусто | < 20 слов | 682 | 33,6 % |

Доля словарных слов по корпусу — 47,7 %, медиана по документам — 42 %. Хорошо распознаются лишь чистые машинописные отчёты (6 из 44 документов выше 70 %). На большинстве страниц Tesseract выдаёт нечитаемый текст, а треть страниц `dense_text` он не распознал совсем. Текстовый слой в текущем виде пригоден для поиска по ключевым словам, но не для чтения и точного извлечения сущностей.

## Эксперимент с настройками OCR

Чтобы понять, почему OCR работает плохо, 50 случайных страниц с плотным текстом из 44 отчётов распознаны в 9 вариантах. Сравнение попарное, на одних и тех же страницах, с бутстреп-интервалами 95 %. Скрипт и полные результаты: [experiments/ocr_tuning](experiments/ocr_tuning/summary.md).

| Изменение | Словарных слов | Правильных слов | Вывод |
|---|---|---|---|
| Исходный вариант: 200 dpi, Оцу | 48,0 % | 3376 | — |
| Без бинаризации | 63,7 % (+15,7 п.) | +34 % | Главный эффект, значим |
| + 300 dpi | 64,1 % | +38 % | Меньше пустых страниц (11 против 15), по качеству разница незначима |
| + модель tessdata_best | 63,9 % | **+44 %** | Значимо больше правильных слов (+2–8 % к 300 dpi), на 30 % медленнее |
| psm 4 / psm 6 | 63,3 / 62,8 % | ≈ | Незначимо |
| Адаптивная бинаризация Саувола | 48,3 % | ≈ исходному | Не помогает |

Бинаризация Оцу стирает тонкие штрихи бледной машинописи; Tesseract лучше работает с оттенками серого. Конвейер переведён на лучшую конфигурацию: без бинаризации, 300 dpi, tessdata_best. Даже она даёт около 64 % словарных слов — это потолок Tesseract на таких сканах; следующий шаг — нейросетевые модели распознавания.

## Структура

### Основной конвейер

| Файл | Назначение |
|---|---|
| `run_pipeline.py` | Запуск конвейера по папке с PDF |
| `config.py` | Пути к внешним программам, словари терминов |
| `preprocess_pages.py` | Предобработка изображения страницы |
| `layout.py` | Типизация страницы |
| `run_ocr.py` | Обёртка над Tesseract |
| `linguistics.py` | Извлечение сущностей, статистика корпуса |
| `reporting.py` | Сохранение результатов |
| `utils.py` | Вспомогательные функции |
| `analyze_results.py` | Сводка по всем документам и классификация документов |
| `evaluate_ocr_quality.py` | Оценка качества OCR без эталона, отчёт в `docs/ocr_quality.md` |
| `experiments/ocr_tuning/run_experiment.py` | Сравнение вариантов предобработки, dpi и моделей Tesseract |

### Данные

| Файл | Назначение |
|---|---|
| `report_urls.txt` | Ссылки на PDF-отчёты в архиве ИА РАН |
| `download_from_list.py` | Скачивание отчётов по списку в `input_reports/` |

### Пилотная версия и датасет планов

Первая версия конвейера, отработанная на 12 отчётах (404 страницы): отдельные скрипты для каждого шага.

`pdf_to_pages.py` → `preprocess_pages.py` → `analyze_pages.py` → `run_ocr.py` → `aggregate_ocr.py` → `analyze_corpus.py` → `extract_entities.py` → `summarize_entities.py` → `show_visualizations.py`

На её основе `build_plans_dataset.py` и `enrich_plans_dataset.py` собирают датасет страниц с планами, схемами и разрезами для будущей CV/ML-классификации.

### Сайт

`dar-site/` — статическая страница со сводной статистикой по пилотному корпусу.

## Установка

Нужны Python 3.10+ и две внешние программы:

- **Tesseract OCR** с русским языком — [установщик для Windows](https://github.com/UB-Mannheim/tesseract/wiki);
- **Poppler** — [сборка для Windows](https://github.com/oschwald/poppler-windows/releases); распакуйте в `tools/` или укажите путь в переменной окружения;
- **модель tessdata_best** — [rus.traineddata](https://github.com/tesseract-ocr/tessdata_best/raw/main/rus.traineddata), положите в `tools/tessdata_best/`. Без неё используется модель, установленная с Tesseract.

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements_minimal.txt
```

Пути к программам задаются в `config.py` или через переменные окружения:

```
set POPPLER_PATH=C:\path\to\poppler\Library\bin
set TESSERACT_EXE=C:\Program Files\Tesseract-OCR\tesseract.exe
set TESSDATA_DIR=C:\path\to\tessdata_best
```

## Запуск

```
python download_from_list.py
python run_pipeline.py --input input_reports --output results --skip-existing
python analyze_results.py
python evaluate_ocr_quality.py
```

`--skip-existing` пропускает уже обработанные отчёты, поэтому обработку можно прерывать и продолжать.

## Данные и права

Исходные отчёты и производные от них материалы (изображения страниц, OCR-тексты) в репозиторий не входят. Они принадлежат Институту археологии РАН и доступны в его [открытом архиве](https://archaeolog.ru/pub/elektronnye-polevye-otchety). Репозиторий содержит только код, список ссылок и сводную статистику.

## Ограничения и планы

- Типизация страниц основана на эвристиках плотности; следующий шаг — обученный классификатор на датасете планов.
- Извлечение сущностей построено на регулярных выражениях и даёт ложные срабатывания; планируется NER-модель.
- Качество OCR низкое (см. выше). Следующие шаги: сравнить OCR до и после бинаризации, повысить dpi рендера, попробовать современные модели распознавания и собрать эталон из 20–30 вручную расшифрованных страниц для расчёта CER/WER.
